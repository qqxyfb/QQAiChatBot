## 1. 概述

### 1.1 背景与目标

当前机器人仅能回复纯文字（`NormalizedMessage.content` / `ReplyPayload.content` 均为 `string`，官方连接器固定 `msg_type: 0`，OneBot 连接器剥离所有 `[CQ:...]`）。本次需求让机器人支持：

1. **表情包**：命中语境时单独发送表情图（不配文字）。
2. **语音**：文字回复可附加 TTS 语音消息。

> 明确**不做**：图片联网搜索（已砍掉）、语音识别（ASR，用户语音转文字）、视频。

### 1.2 设计原则

| 原则 | 说明 |
| --- | --- |
| 向后兼容 | 富媒体通过可选 `segments` 字段承载，缺省时仍按 `content` 走纯文本，旧连接/旧逻辑不受影响 |
| 资源池 + 覆盖 | 表情包组、TTS 均遵循「全局资源池默认 + 人格级绑定/覆盖」，连接绑定人格后自动继承 |
| 语义与多样性分离 | 表情选择分两级：LLM 做语义决策（选标签），标签内随机选文件（保多样性） |
| 受控输出 | LLM 只在给定标签枚举内输出表情标记，非法/空一律降级纯文字，绝不因解析失败崩溃 |
| 渠道无关 | 连接器统一消费 `Segment[]`，各自翻译成官方 API / OneBot 消息体 |

### 1.3 术语

沿用《详细设计文档 v1.1》术语，新增：

| 术语 | 定义 |
| --- | --- |
| 消息段（Segment） | 回复消息的最小承载单元：文本 / 表情包 / 语音 |
| 表情包组（StickerSet） | 表情包的集合与归属单元，全局资源池，可被多个人格引用 |
| 标签（Tag） | 表情文件的关键字，一张图可多标签；LLM 输出的表情标记取值域 |
| 两级选择 | LLM 选标签 + 标签内随机选文件 的表情选择机制 |
| TtsProvider | TTS 厂商适配抽象，统一 `synthesize(text)` 输出音频 |

## 2. 总体设计

### 2.1 归属层级

```
全局资源池（默认）
  ├─ 表情包组库：组1 / 组2 / 默认组
  └─ 全局 TTS 默认配置
        │  继承 / 覆盖
人格（Persona JSON 档案，导入即用）
  ├─ stickerSet?: string      # 绑定组 id，未绑回退默认组
  └─ voice?: { enabled, tts? } # 语音开关 + 可选 TTS 覆盖
        │  绑定
连接（Connection）── 富媒体与语音随人格生效
```

### 2.2 回复消息改造全景

```
NormalizedMessage(纯文本)
  └─ Pipeline: 触发→名单→上下文→安全→LLM→安全(出)
        │
        ▼
  ⑧ 媒体决策 MediaPlanner（新增）
     ├─ 解析 [sticker:标签] → 命中→表情包 Segment（单独发）
     ├─ 未命中 → 文本 Segment
     └─ voice.enabled 且为文字 → 调 TTS 追加语音 Segment
        │
        ▼
  ⑨ 回复 sendReply(segments) → 连接器翻译为富媒体消息
```

## 3. 消息段模型（Segment）

```ts
export type Segment =
  | { type: 'text';    text: string }
  | { type: 'sticker'; stickerId: string; path: string; alt: string }
  | { type: 'voice';   path: string; duration: number };   // duration 秒

export interface ReplyPayload {
  messageId: string;
  content: string;                 // 纯文本（日志/兜底/历史回放用）
  segments?: Segment[];            // 富媒体段，缺省时连接器按 content 发纯文本
  channel: Channel;
  fromId?: string;
  groupId?: string;
}
```

- `content` 恒为回复的纯文本（表情包场景下为去标记后的文字，可能为空串）。
- 连接器 `sendReply` 判定：`segments` 非空且长度 > 0 → 逐段翻译；否则回退 `content` 纯文本（与现状一致）。

## 4. 表情包库设计

### 4.1 数据与存储

```
data/stickers/<setId>/<标签>_<序号>.<ext>      # 文件名约定自动打标签
data/stickers/<setId>/<标签>/<任意>.<ext>      # 子目录约定自动打标签（二选一）
```

```sql
CREATE TABLE IF NOT EXISTS sticker_set (
  id         TEXT PRIMARY KEY,              -- uuid
  name       TEXT NOT NULL,
  is_default INTEGER DEFAULT 0,
  created_at INTEGER
);

CREATE TABLE IF NOT EXISTS sticker (
  id         TEXT PRIMARY KEY,              -- uuid
  set_id     TEXT NOT NULL,
  file_name  TEXT NOT NULL,
  file_path  TEXT NOT NULL,                 -- 相对 data/ 的路径
  tags       TEXT NOT NULL,                 -- JSON 数组，如 ["开心","笑"]
  created_at INTEGER
);
CREATE INDEX IF NOT EXISTS idx_sticker_set ON sticker(set_id);
```

### 4.2 标签倒排索引（内存缓存）

复用 `BanwordRepo` 的缓存模式：启动时从 `sticker` 表加载全部 → 按组建倒排索引：

```ts
// src/media/sticker-index.ts
export interface StickerIndexEntry { id: string; path: string; alt: string; }
export type StickerIndex = Map<string /* set_id */, Map<string /* tag */, StickerIndexEntry[]>>;

export class StickerRepo {
  private cache: StickerIndex | null = null;
  load(): void;                                  // 启动加载到内存
  getCache(): StickerIndex;                      // 运行时零 SQL
  getCandidates(setId: string, tag: string): StickerIndexEntry[];
  add(setId: string, sticker: { fileName; path; tags }): void;   // 写 DB + 同步缓存
  remove(stickerId: string): void;
  listSets(): StickerSet[];                      // 组列表
}
```

> `alt` 取文件名（去标签前缀），供日志/无障碍描述。

### 4.3 导入与打标签（两件套）

| 方式 | 规则 | 适用 |
| --- | --- | --- |
| 文件名约定自动打标签 | `开心_01.png` → 标签「开心」；或 `开心/xxx.png` → 目录名「开心」 | 批量导入、开箱即用 |
| 界面手动打标签 | 表格里每张图增删标签（一张图可多标签）、改所属组 | 微调、补标签 |

导入流程（`StickerService.import`）：

1. 接收文件（`multipart` 上传或 base64 列表），确定目标组（默认组 / 指定组）。
2. 解析标签：文件名前缀 `<标签>_` 或父目录名；无约定时标签置空，等用户在界面补。
3. 文件落盘 `data/stickers/<setId>/`（重名加序号），写 `sticker` 表 + 刷新内存索引。
4. 返回导入结果：`{ total, tagged, untagged }`。

> 内置 1 个「默认组」+ 少量示例表情，保证未配置人格时也能开箱即用。

### 4.4 人格绑定

`Persona` 新增可选字段 `stickerSet?: string`。解析人格时：

```ts
const set = persona.stickerSet ?? defaultSet.id;   // 未绑回退默认组
```

## 5. 两级选择机制（表情包）

### 5.1 触发与决策

- 表情包**只在 LLM 语义决策下发**，不做关键词写死命中（避免退化成规则引擎）。
- LLM 输出协议：在回复文本中输出标记 `[sticker:标签]`，`标签` 必须 ∈ 当前人格所绑组的标签枚举。
- 标签枚举由 `PromptBuilder` 注入提示词（见 5.3）。

### 5.2 MediaPlanner 装配

```ts
// src/pipeline/media-planner.ts
export interface PlanResult {
  segments: Segment[];
  hasText: boolean;               // 是否含文字（决定是否附加语音）
}

export class MediaPlanner {
  plan(text: string, persona: Persona, index: StickerIndex): PlanResult {
    const tag = parseStickerTag(text);               // /\[sticker:([^\]]+)\]/
    if (tag) {
      const set = persona.stickerSet ?? DEFAULT_SET_ID;
      const candidates = index.getCandidates(set, tag);
      if (candidates.length > 0) {
        const pick = candidates[Math.floor(Math.random() * candidates.length)];
        return { segments: [{ type: 'sticker', stickerId: pick.id, path: pick.path, alt: pick.alt }], hasText: false };
      }
      // 标签合法但无候选文件 → 降级纯文字
    }
    return { segments: [{ type: 'text', text: stripStickerTag(text) }], hasText: true };
  }
}
```

- 命中表情包 → **单独发送、不配文字**（`hasText:false`，`content` 置空）。
- 标签非法 / 无候选 → 剥掉标记按纯文字回复，不报错。

### 5.3 标签枚举注入（PromptBuilder 扩展）

```ts
// 当 persona.stickerSet 绑定且该组有标签时，在 profilePrompt 后追加：
//
// 「回复末尾可用 [sticker:标签] 表示发送表情包（仅可选用以下标签，且只发图不配字）：
//   开心、难过、笑、生气、贴贴、摸头、晚安……
//   若不适合发表情包则不要输出该标记。」
```

## 6. TTS 语音设计

### 6.1 触发方式（配置驱动）

语音**不参与 LLM 逐条决策**，由人格级开关控制（有延迟/成本，默认关）：

```ts
export interface VoiceConfig {
  enabled: boolean;          // 默认 false
  tts?: TtsConfig;           // 可选覆盖，缺省用全局默认
}
```

- `voice.enabled === true` 且本条回复为文字（`hasText === true`）→ 对文字做 TTS，**追加**一条语音段（文字 + 语音都发）。
- 表情包回复（`hasText === false`）不附加语音。

### 6.2 TTS 多厂商抽象

```ts
export type TtsProviderType = 'openai-compatible' | 'edge';

export interface TtsConfig {
  provider: TtsProviderType;
  baseUrl?: string;            // openai-compatible 必填
  apiKey?: string;             // SecretStore 加密（edge 无需）
  voice: string;               // 音色
}

export interface TtsProvider {
  readonly type: TtsProviderType;
  synthesize(text: string, cfg: TtsConfig): Promise<{ audio: Buffer; format: 'mp3' | 'wav' | 'opus' }>;
}

export class TtsGateway {
  constructor(private cfg: TtsConfig, private emit: (e: MetricEvent) => void) {}
  async synthesize(text: string): Promise<TtsResult>;
  // 流程：provider.synthesize → 转码 silk/amr（ffmpeg + silk 编码器）→ 落盘 → 返回 filePath
}
export interface TtsResult { ok: boolean; filePath: string; format: 'silk' | 'amr'; duration: number; error?: string; }
```

内置两个 Provider：

| Provider | 接口 | 说明 |
| --- | --- | --- |
| `openai-compatible` | `POST {baseUrl}/audio/speech`（OpenAI 兼容） | 覆盖多数云厂商（含硅基流动、智谱等） |
| `edge` | Edge TTS（WebSocket / `edge-tts`） | 免费、无需 key、音色多，作默认兜底 |

- 供应商在**全局配置**（默认）+ **人格 JSON**（覆盖）下拉选择，对齐 LLM 的「全局 + 覆盖」模式。
- 失败降级：TTS 失败仅记日志、**只发文字**，不阻塞回复。

### 6.3 转码（实现调整）

- **实现调整**：本版 TTS 直接输出 mp3，**不做 silk 转码**。
  - OneBot：`[CQ:record,file=<mp3 路径>]`，由 NapCat 内部自动转码发送；
  - 官方 bot：上传 mp3（`file_type=3` 语音）发富媒体。
- 后续如需官方 bot 精确 silk 格式，可再加 ffmpeg 转码步骤（`TtsGateway` 已预留该位置）。
- 风险标注：官方 bot 语音的 media 结构以 QQ 开放平台当前文档为准，需联调。

## 9. 连接器富媒体发送（connectors）

### 9.1 能力矩阵

| 段类型 | 官方机器人（API v2） | OneBot / NapCat |
| --- | --- | --- |
| text | `msg_type:0` + `content` | `message` 纯文本 |
| sticker | 按**图片**发送（富媒体，先上传拿 `file_info`） | `[CQ:image,file=<path>]` |
| voice | 富媒体 audio（先上传 silk 拿 `file_info`） | `[CQ:record,file=<path>]` |

> 官方 bot 无原生「表情」类型，表情包一律按图片发送。

### 9.2 OfficialBotConnector.sendReply 扩展

```ts
async sendReply(r: ReplyPayload): Promise<void> {
  if (!r.segments || r.segments.length === 0) { /* 走原纯文本逻辑 msg_type:0 */ return; }
  for (const seg of r.segments) {
    if (seg.type === 'text') await this.sendText(r, seg.text);
    else if (seg.type === 'sticker') await this.sendImage(r, seg.path);
    else if (seg.type === 'voice') await this.sendAudio(r, seg.path);
  }
}
// sendImage/sendAudio：POST /v2/groups|users/{id}/files 上传 → 拿 file_info → 发送富媒体消息（media 类型 image/audio）
// 具体 media 结构以 QQ 开放平台当前文档为准，联调确认。
```

### 9.3 AccountLoginConnector.sendReply 扩展

```ts
async sendReply(r: ReplyPayload): Promise<void> {
  const msg = this.buildMessage(r);   // 将 segments 拼成 OneBot message 段数组
  // [text]  → { type:'text', data:{ text } }
  // [sticker] → { type:'image', data:{ file: seg.path } }
  // [voice]   → { type:'record', data:{ file: seg.path } }
  this.ws.send(JSON.stringify({ action, params: { ..., message: msg }, echo }));
}
```

## 10. Pipeline 改造（`src/pipeline/index.ts`）

在现有 ⑦ 安全(出) 之后插入 ⑧ 媒体决策，⑨ 回复改用 segments：

```ts
// ⑦ 安全(出)
const out = res.ok ? SafetyFilter.checkOut(res.text, banwords, personaBanned) : res.text;

// ⑧ 媒体决策（新增）
const plan = new MediaPlanner().plan(out, persona, stickerIndex);
if (plan.hasText && persona.voice?.enabled) {
  const tts = await new TtsGateway(resolveTts(persona, globalTts), emit).synthesize(planText);
  if (tts.ok) plan.segments.push({ type: 'voice', path: tts.filePath, duration: tts.duration });
}

// ⑨ 回复 + 打点
await this.reply(m, { segments: plan.segments, content: textOf(plan) }, finish, res, t0);
```

- `reply()` 内部 `sendReply({ ..., segments })`；`emit message` 事件的 `reply` 字段仍存纯文本（含去标记后的文字），便于历史检索。
- `ctx.push` 上下文只存**纯文本**（表情包/语音不入上下文，避免污染 LLM 上下文）。

```
      └─ TtsConfigSection         # 全局默认 TTS（厂商/音色/测试试听）
```

## 15. 关键流程伪代码

### 15.1 表情包发送

```
用户「哈哈笑死我了」
  → Pipeline → LLM 返回「[sticker:大笑]」
  → MediaPlanner.plan: tag=「大笑」, 组=默认组
      candidates = index.getCandidates('default','大笑')   // N 张
      pick = random(candidates)
      → segments=[{sticker: pick}], hasText=false
  → sendReply(segments) → 连接器按图片发送（单独、无文字）
```

### 15.2 语音附加

```
voice.enabled=true，用户「讲个笑话」
  → LLM 返回纯文字（无 [sticker:]）
  → MediaPlanner.plan: hasText=true, segments=[{text}]
  → TtsGateway.synthesize(text) → silk 文件
  → segments.push({voice})
  → 连接器发送：文字 + 语音 两条
```

## 17. 测试要点

| 模块 | 重点用例 |
| --- | --- |
| 消息段 | 纯文本缺省 segments 回退、多段顺序发送、空 segments 兜底 |

| 转码 | mp3→silk、格式错误降级 |
| 连接器 | 官方 bot 图片/语音上传、OneBot `[CQ:image]`/`[CQ:record]` 拼装 |
| 上下文 | 表情包/语音不入 LLM 上下文、历史 reply 只存纯文本 |

## 18. 风险与开放问题

| 风险 / 问题 | 等级 | 应对 |
| --- | --- | --- |
| 官方 bot 无原生表情类型 | 中 | 表情包统一按图片发送 |
| QQ 语音 silk 转码依赖 ffmpeg | 高 | 随包附带 ffmpeg 或声明运行依赖；优先验证 OneBot 直接发 mp3 的兼容性 |
| LLM 输出 `[sticker:]` 标记不稳定 | 中 | 标签枚举注入 + 正则解析 + 非法降级纯文字，绝不崩溃 |
| 富媒体消息体结构随 QQ 平台变化 | 中 | 隔离在连接器内，联调时以官方文档为准 |
| TTS 成本/延迟 | 中 | 语音默认关闭；失败只发文字；后续可限长/异步 |
| 表情包版权 | 低 | 内置示例用无版权素材；用户自导图片自担 |
