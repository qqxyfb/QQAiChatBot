## 1. 项目概述

### 1.1 项目定位

构建一个**可自由配置、易上手**的 AI 聊天机器人**多连接管理后台**：用户在一个控制台内创建并管理**多个 QQ 连接**（多个官方机器人 / 多个登录 QQ 号），每个连接独立配置连接属性、人格、流量控制，一键启停，并统一查看运行日志、数据统计、使用消耗与聊天记录（可按连接切换）。

相比 v1.x 的「单连接工具」，v2.0 定位为**多连接总后台**：以「连接（Connection）」为核心实体，实现「一套程序，管理多个 bot」。

### 1.2 项目目标

1. **跨平台运行**：Windows 下以 `exe` 客户端程序为入口（原生窗口，亦可网页访问）；Linux 下为纯后台进程，通过浏览器访问服务页面。
2. **多连接管理**：支持创建 / 删除 / 启停**多个连接**；每连接可独立选择「QQ 官方机器人」或「登录 QQ 号」接入方式。
3. **连接独立配置**：每个连接独立配置连接属性、绑定人格、流量控制（白黑名单 / 上下文 / token 预算 / 限流 / 触发规则）。
4. **人格资源库**：人格作为全局资源池，导入/归档/预览/生成/删除，可被多个连接引用，**无需授权鉴权**。
5. **配置可视化**：全局配置与连接级配置均在页面内完成，无需手改文件。
6. **可观测**：运行日志（连接 + LLM 调用）动态刷新、按连接筛选；数据统计与使用消耗以图表呈现（支持全局汇总 + 单连接），token 折算为实际费用。
7. **聊天记录留存**：展示对话人与回复记录，支持按连接筛选、检索与导出。
8. **一键启停**：每连接独立启停 + 全部启停。
9. **检测更新**：内置版本更新检测与升级能力。

### 1.3 项目范围（本期）

**包含**：多连接管理、核心配置（全局 + 连接级）、连接级聊天配置、人格管理（资源库）、运行日志、数据统计、使用消耗、聊天记录、连接启停、人格格式帮助文档、跨平台运行形态、更新检测。

**不包含**（后续迭代）：
- 大模型本地部署 / 微调训练。
- 除 QQ 外的其他 IM 渠道（微信 / 钉钉 / Telegram）。
- 多租户 / 团队协作 / 云端管理。
- 语音 / 视频消息识别。

## 2. 参考项目分析结论（借鉴与优化）

> 本节为「分析学习 AmasuzuRinBot 后的结论」，用于说明本需求的设计取舍依据。

### 2.1 值得借鉴的设计

| 借鉴点 | 说明 | 本项目落地方式 |
| --- | --- | --- |
| `[METRIC]{json}` 结构化打点 | 业务层每次回复向 stdout 输出一行 JSON，客户端解析落库 | 沿用：连接器 / LLM 网关统一打点，`服务核心` 解析落 SQLite（补 `connectionId` 维度） |
| SQLite 单机零运维 | 指标 / 历史 / 会话本地落库，免部署数据库 | 沿用 |
| 成本折算 ¥ | `(prompt_tokens × 输入单价 + completion_tokens × 输出单价) / 1e6` | 沿用，单价按模型可配 |
| `config.json` 单一配置源 | 页面保存 → 落盘 → 运行时读取，避免手改 `.env` | 沿用 |
| 日志分来源 / 级别 | 客户端 / 接入层 / 业务层分色展示 | 简化为「服务 / 连接器 / LLM」三源，补连接维度 |
| 白名单 + 防滥用 | 群白名单、每日 token 预算、输入长度上限 | 沿用，下沉到**连接级**，并扩展黑名单模式 |
| 人格档案 JSON 化 | `profilePrompt` + `sampleDialogues` + `bannedWords` 结构化 | 沿用，去掉 `authorization` 字段，改为全局资源池 |
| PyInstaller 单文件 exe | 打包只读资源，配置/数据外置 | 沿用（打包方式随技术栈调整） |

### 2.2 本项目的关键优化

| # | 优化点 | 原项目问题 | 本项目方案 |
| --- | --- | --- | --- |
| O1 | **技术栈简化** | Java + Python 三层，部署重 | **单进程 TypeScript/Node.js 服务**（首选）：一体化，跨平台易打包；Python 为备选 |
| O2 | **连接器抽象** | 仅官方 bot API v2 一种接入 | 抽象「连接器」，支持官方 bot / 登录 QQ 号（OneBot v11）两种，可切换 |
| O3 | **去授权门槛** | 人格 `GRANTED` 鉴权 | 人格**无需鉴权**，保留安全红线 + 内容过滤 |
| O4 | **跨平台形态** | 仅 Windows 桌面客户端 | Windows 安装版 + 便携版；Linux 纯后台 + systemd |
| O5 | **更新检测** | 无 | 版本号 + 更新源，启动/手动检查，可选自动下载升级 |
| O6 | **黑名单模式** | 仅白名单 | 白名单 / 黑名单二选一，作用于「群 + 对象」两级 |
| O7 | **多连接后台** | 单连接单配置 | 「连接」提升为一级实体，支持多连接，各连接独立配置与流量控制 |

## 3. 术语定义

| 术语 | 定义 |
| --- | --- |
| **服务核心** | 本项目的单进程后台服务，托管 Web 页面与 REST API，负责全局配置、连接编排、LLM 网关、日志、指标、历史、更新检测 |
| **连接（Connection）** | 一级实体：一个可独立运行的 QQ 接入实例，包含连接属性、人格绑定、流量控制等独立配置；运行时为一个连接器实例 |
| **连接器（Connector）** | 连接的具体实现：官方机器人 / 登录 QQ 号两种，负责收发消息与连接状态上报 |
| **官方机器人** | 通过 QQ 开放平台 `AppID + AppSecret` 接入官方机器人 API v2，群 @ / 私聊 C2C |
| **登录 QQ 号** | 通过 NapCat / OneBot v11 协议，使用本人 QQ 号登录收发消息（第三方协议，有风控风险，用户自担） |
| **全局配置** | 服务级配置：LLM 默认配置、存储、服务端口、更新源等，对全部连接生效 |
| **连接级配置** | 每个连接独立的配置：连接属性、人格绑定、白黑名单、上下文、token 预算、限流、触发规则、LLM 覆盖（可选） |
| **人格（Persona）** | 全局资源池中的 JSON 档案，描述人设；可被多个连接引用 |
| **会话（Session）** | 某连接一次「启动 → 停止」的运行周期 |
| **LLM 网关** | 封装 OpenAI 兼容 `/chat/completions` 调用，含超时、重试、token 统计、打点 |
| **对话人 / 对象** | 与某连接交互的群或用户（openid / QQ 号，一律脱敏哈希展示） |

## 4. 用户角色与使用场景

| 角色 | 说明 | 主要诉求 |
| --- | --- | --- |
| 主用户（后台所有者） | 部署、配置、维护多个 bot | 管理多个连接、各自配置、分别启停、按连接看日志/统计/记录 |
| 维护者 | 排查问题 | 按连接看日志与 LLM 调用、错误率、上游健康 |
| 群成员 / 私聊用户 | 与某连接交互的普通用户 | 获得自然、贴合人设的回复 |

**典型流程**：安装/启动 → 打开服务页 → 完成全局配置（LLM/存储）→ 创建连接 → 配置连接属性 + 绑人格 + 流量控制 → 启动该连接 → 按连接看日志/统计 → 需要时增删连接 / 更新。

## 5. 总体架构设计

### 5.1 架构图

```
┌──────────────────────────────────────────────────────────────┐
│               服务核心（单进程，TypeScript/Node.js）            │
│  ┌────────────────────────────────────────────────────────┐  │
│  │  Web 界面层  React/Vue + ECharts                         │  │
│  │  （全局配置/连接管理/人格/日志/统计/消耗/记录/启停）       │  │
│  └───────────────────────────┬────────────────────────────┘  │
│  ┌───────────────────────────▼────────────────────────────┐  │
│  │           本地 REST API + 静态资源 + WebSocket           │  │
│  └────────┬───────────────────────────────────────────────┘  │
│           │                                                    │
│  ┌────────▼─────────┐ ┌────────────────────────────────────┐ │
│  │   连接管理器       │ │ 人格资源库 │ LLM网关 │ 更新检测      │ │
│  │  ConnectionManager│ └───────────┴─────────┴─────────────┘ │
│  └────────┬─────────┘                                          │
│           │ 每连接一个连接器实例（可并发运行）                    │
│  ┌────────▼─────────────────────────────────────────────┐      │
│  │  连接器实例 × N                                          │      │
│  │  [连接1:官方bot] [连接2:登录QQ号] [连接3:官方bot] ...      │      │
│  └────────┬─────────────────────────────────────────────┘      │
│           │ 各自消息 → 各自核心链路                              │
│  ┌────────▼─────────────────────────────────────────────┐      │
│  │  核心链路（每连接独立）：触发→白黑名单→上下文→安全→LLM→回复 │      │
│  └────────┬─────────────────────────────────────────────┘      │
│           │ 打点落库（带 connection_id）                          │
│           ▼                                                     │
│     SQLite（连接/指标/历史/会话/配置快照）                        │
└──────────────────────────────────────────────────────────────┘
         ▲（事件/发送）                    ▲（HTTP）
   QQ 官方 API v2 / NapCat·OneBot     大模型 API（OpenAI 兼容）
```

### 5.2 关键技术选型（TS 首选 / Python 备选）

> **结论**：推荐 **TypeScript/Node.js** 作为首选技术栈，Python 为备选。二者均为「单进程服务」形态，架构图一致，差异在具体实现与打包。

#### 5.2.1 方案对比

| 维度 | A. TypeScript/Node.js（推荐） | B. Python（备选） |
| --- | --- | --- |
| 前后端一致性 | 全栈同语言，UI 与 API 共享类型定义 | UI 用 JS、后端用 Python |
| 官方 bot 接入 | 官方 Node SDK / 社区 `qq-official-bot`（TS） | `qq-botpy` |
| 登录 QQ 号接入 | Node 生态成熟（`icqq` / NapCat / OneBot v11 均为 Node） | OneBot v11 需自实现 WS 客户端 |
| 多连接并发 | 事件驱动，天然支持多 WS 长连接 | asyncio 支持 |
| 存储 | `node:sqlite`（内置，免编译）或 `better-sqlite3` | 内置 `sqlite3` |
| Windows 打包 | Node SEA / Tauri / Electron | PyInstaller |
| 类型安全 | 强（TS） | 弱（可加 mypy） |

#### 5.2.2 技术选型表（以 TS 方案为例）

| 层次 | 选型 | 说明 |
| --- | --- | --- |
| 服务核心 | Node.js 22 LTS / 24 LTS + TypeScript | 单进程，多连接并发 |
| Web 后端 | Fastify（或 Express / NestJS） | 静态资源 + REST + WebSocket |
| Web 前端 | React / Vue + Vite + ECharts | 类型共享；图表 |
| 官方 bot 接入 | 官方 Node SDK 或 `qq-official-bot` | WS 鉴权 / 心跳 / 被动回复 |
| 登录 QQ 号接入 | OneBot v11（对接 NapCat / `icqq`） | Node 生态成熟 |
| LLM 网关 | `openai` npm（OpenAI 兼容） | 重试 / 超时 / token 统计 |
| 存储 | `node:sqlite` / `better-sqlite3` | 单机零运维 |
| Windows 打包 | Node SEA（便携）/ Tauri 或 Electron（安装） | 原生窗口可回退浏览器 |
| Linux 部署 | Node 直跑 + systemd | 纯后台 |
| 更新检测 | 版本号 + 更新源 | 见 FR1.3 |

### 5.3 连接器抽象（对应 O2）

```
连接器（Connector）接口：
  - connect() / disconnect()
  - 事件回调：on_message（归一化为 {connectionId, channel, fromId, groupId, content, atBot}）
  - send_reply(reply, 幂等标识)
  - 状态上报：连接中 / 已连接 / 断线 / 心跳

实现：
  - OfficialBotConnector   基于官方/社区 Node SDK（AppID + AppSecret）
  - AccountLoginConnector  基于 OneBot v11 / NapCat / icqq（QQ号登录，WS 收发）
```

连接管理器（`ConnectionManager`）维护**多个连接器实例**（每个连接一个），向上暴露统一的连接生命周期与消息入口；核心链路不感知连接器差异，但**每连接独立运行**（独立上下文、独立流量控制、独立打点）。

## 6. 功能需求（FR）

### FR1 服务运行形态（跨平台 + 更新检测，P0）

#### FR1.1 Windows 运行形态

- 提供两种发行形态：**安装版 `setup.exe`**（见 FR1.4）与**便携版 `QQAiChatBot.exe`**（单文件）。
- 启动后，在本地回环（默认 `127.0.0.1`，默认端口如 `8700`）拉起服务核心，并默认以**原生窗口**打开服务页面（可选 Tauri / Electron / Neutralino；未启用时回退系统浏览器）。
- 提供命令行参数：`--browser`、`--port N`、`--check`、`--no-window`。
- 用户也可**直接浏览器访问** `http://127.0.0.1:8700` 使用同一页面。

#### FR1.2 Linux 运行形态

- 提供纯后台进程入口（`run.sh` / systemd unit），无图形界面，仅启动服务核心。
- 通过浏览器访问 `http://<host>:8700` 使用服务页面。
- 支持 `systemd` 常驻：崩溃自动重启、开机自启、日志落盘。

#### FR1.3 更新检测（P0 检测 / P1 自动升级）

- 服务内置**版本号**（如 `0.1.0`）。
- 更新源对接 **GitHub Release**（`GET /repos/<owner>/<repo>/releases/latest`）：版本号取 `tag_name`，更新说明取 release `body`，各平台产物（安装版 / 便携版 / Linux 包）作为 release asset，附 `*.sha256` 校验文件。
- 行为：启动时静默检测（可选开关）+ 手动检测；发现新版本横幅提示；下载升级（P1）前校验 `sha256`。
- 更新检测失败不阻塞服务。

#### FR1.4 Windows 安装功能（P0）

- 提供**安装版**（`setup.exe`，Tauri bundler / electron-builder / Inno Setup / NSIS）与**便携版**（绿色单文件）两种发行形态。
- 安装版：安装向导（目录/快捷方式/开机自启）、控制面板卸载项、覆盖升级保留数据、数据分离（`%APPDATA%\QQAiChatBot\`）、卸载可选保留/删除数据。
- 便携版：免安装，数据存同目录 `data\`。
- 均内置版本信息与数字签名。

### FR2 核心配置（P0）

> 所有配置在页面内完成，保存即落盘为 `config.json`（密钥加密存储，见第 8 节）。配置分为**全局配置**与**连接级配置**两层。

#### FR2.1 全局配置

| 分组 | 字段 | 说明 |
| --- | --- | --- |
| LLM（默认） | `baseUrl`、`apiKey`、`model`、`temperature`/`maxTokens` 等 | 全部连接的默认 LLM；提供「测试连接」按钮 |
| 存储 | `dataDir`、`historyRetentionDays`、`logRetentionDays` | 数据目录与保留策略 |
| 安全过滤 | 全局违禁词库（输入/输出方向） | 全局黑名单词，与人格红线词叠加生效 |
| 服务 | `port`、外网访问开关（默认关）、访问令牌 `accessToken` | 外网访问开启时**强制要求**配置访问令牌，外部请求需鉴权 |
| 更新 | 更新源仓库、启动静默检测开关 | GitHub Release 更新源 |

#### FR2.2 连接管理（多连接，P0）

- 提供**连接列表**：展示每个连接的名称、类型（官方/账号）、状态（运行/停止/异常）、绑定人格、今日消息/token（概览）。
- **新建连接**：填写连接名称（自动生成 `connectionId`）、选择连接类型。
- **删除连接**：删除前确认；运行中需先停止。
- **复制连接**（P1）：以现有连接为模板快速新建。
- 每个连接进入**连接详情页**，独立配置以下内容（见 FR2.3 / FR3）。

#### FR2.3 连接属性配置（连接级）

| 字段 | 说明 |
| --- | --- |
| 连接类型 | `official`（官方机器人）/ `account`（登录 QQ 号） |
| 官方机器人 | `appId`、`appSecret`、`apiDomain`、可选 `botToken` |
| 登录 QQ 号 | 协议（NapCat/OneBot v11）、`host`、`port`、`accessToken`（可选）、正向/反向 WS |
| 意图订阅 | 群 @ 消息、私聊 C2C 消息（官方 bot 需开启对应能力） |
| **人格绑定** | 从人格资源库选择一个人格绑定到本连接（见 FR4） |
| **LLM 覆盖**（P1） | 可选：本连接覆盖全局 LLM 配置与单价 |

- 选择「登录 QQ 号」时，页面**弹窗提示封号风险**，用户勾选「已知晓风险」确认后（记录 `riskConfirmed: true`）才允许保存；未确认禁止保存与启动。
- 「测试连接」按钮：验证当前连接凭据与依赖可用性。

### FR3 聊天配置（连接级，P0）

> 以下配置均为**连接级**：每个连接独立设置，互不影响。

#### FR3.1 白名单 / 黑名单模式

| 模式 | 语义 |
| --- | --- |
| **白名单模式** | 仅名单内的「群 + 对象」可被响应，其余静默 |
| **黑名单模式** | 名单内的「群 + 对象」不响应，其余正常响应 |

- 名单分两级：**群（group）** 与 **对象（user）**；两种模式二选一；支持增删改、批量导入、去重。

#### FR3.2 聊天上下文数量配置

| 字段 | 说明 |
| --- | --- |
| `contextMaxMessages` | 每群/每对象独立上下文最大条数（超出截断） |
| `contextTtlMinutes` | 上下文过期时间（如 5 分钟无对话清空） |

#### FR3.3 Token 消耗限制（流量控制）

| 字段 | 说明 |
| --- | --- |
| `dailyTokenBudget` | **本连接**每对象每日 token 预算（超限当日不再回复该对象） |
| `maxInputLen` | 单条输入最大长度 |
| `floodThreshold` | 灌水检测阈值（短时高频熔断） |
| `rateLimit` | 本连接单位时间最大回复次数 / 消息间隔 |
| `budgetAlertPct` | 预算告警线（如 80%） |

- 命中限制时回复预设兜底语并记录 `abuse_event`（脱敏，带连接维度）。

#### FR3.4 触发规则（P1）

| 模式 | 说明 |
| --- | --- |
| 仅 @ 回复（默认） | 群内被 @ 才回复 |
| 关键词触发 | 命中指定关键词自动回复 |
| 概率闲聊 | 无人 @ 时按概率主动插话（需限流） |
| 静默模式 | 一键暂停本连接所有回复 |

### FR4 人格管理（资源库，P0）

> 人格作为**全局资源库**，**不再有「当前人格」概念**；人格绑定在连接详情页（FR2.3）完成。**无需授权鉴权**，导入即用。

#### FR4.1 人格归档管理

- 扫描人格库目录（默认 `personas/`）下 `persona_*.json`，列出：名称、风格、标签、示例对话数、创建/修改时间、是否内置、**被哪些连接引用**。
- 支持**导入**（文件/目录批量）、**删除**、**导出**、**重命名**。
- 导入时**格式校验**（见 FR9 / 附录），缺失必需字段（`name`、`profilePrompt`）标红并禁止被连接选用。

#### FR4.2 人格展示

- 展示某人格配置：画像、标签、情绪风格、示例对话（前 N 组）、安全红线词、系统提示词预览、被引用连接列表。

#### FR4.3 默认人格

- 内置 1~N 个**默认人格**（只读或可复制后编辑）；新建连接未绑定时回退到默认人格；默认人格不可删除。

#### FR4.4 在线编辑与生成（P1 编辑 / P0 生成）

- **生成**：输入人设描述 / 示例对话 → 调用 LLM 生成结构化人格 JSON（**无需鉴权**），预览后保存。
- **编辑**（P1）：页面内编辑画像、标签、示例对话、安全红线词，保存为新版。

### FR5 运行日志（P0）

#### FR5.1 日志来源与内容

| 来源 | 内容 |
| --- | --- |
| 服务核心 | 全局启停、连接增删、配置变更、异常、更新检测 |
| 连接器 | 某连接的 QQ 连接建立/断线/心跳、收到事件、发送结果、去重、风控拦截 |

#### FR5.2 日志展示与交互

- **动态刷新**：增量追加（WebSocket 或轮询 `since` 游标）；提供「暂停/继续」「清屏」「导出」。
- **筛选**：
  - 按**连接**（全部 / 指定连接）。

  - 按**级别**（DEBUG / INFO / WARN / ERROR），分色显示。

- 内存保留最近 N 行，完整日志落文件（按连接 + 来源分文件、按天滚动）。

### FR6 数据统计与使用消耗（P0）

> 设计原则：能回答「用得多不多（成本）、和谁在聊（对象）、答得快不快/稳不稳（质量）」。**支持全局汇总视图与单连接视图**（顶部切换「全部连接 / 指定连接」）。

#### FR6.1 概览卡片（KPI）

运行时长、消息数、Token（输入/输出/总量）、费用（¥）、活跃对象数、**连接数（运行中/总数）**、错误率、拦截数。单连接视图仅统计该连接。

#### FR6.2 图表

| 图表 | 说明 |
| --- | --- |
| Token 消耗趋势 | 按小时（今日）/ 按天（7d/30d），折线或堆叠柱 |
| 消息量趋势 | 与 Token 同步，分群 / 私聊 |
| **时段 Token 消耗** | 按小时聚合 Token，展示日内消耗高峰时段 |
| 延迟分布 | 端到端延迟直方图 + P50 / P95 / P99 |
| 结果分布 | normal / refuse / limit / abuse / error / unauthorized 占比 |
| Top 消耗对象 | 按对象聚合 token / 费用排行（脱敏） |
| 预算使用率 | 今日预算仪表盘（单连接视图） |
| **分连接对比**（P1） | 多连接并列的 token / 消息对比图 |

#### FR6.3 成本折算

- 配置**单价**：`inputPrice`、`outputPrice`（元/百万 token），按模型分别计价（P1）。
- 费用 = `(prompt_tokens × inputPrice + completion_tokens × outputPrice) / 1e6`。
- 展示今日 / 近 7 天 / 近 30 天费用、月度预估；未配置单价显示「未计价」。

#### FR6.4 时间范围与下钻

- 时间范围：今日 / 近 7 天 / 近 30 天 / 自定义。
- 图表支持下钻（点某日 / 某对象 → 进入明细，联动 FR7）。

### FR7 聊天记录（P1）

- **连接筛选**：顶部按连接过滤（全部 / 指定连接）。
- **会话列表**：按对象（群/用户，脱敏哈希）分组，显示最后时间、消息数、累计 token。
- **消息详情**：入/出方向、原文、回复、结果（`finishReason`）、输入/输出 token、业务耗时、端到端耗时。
- **检索**：按时间范围、渠道、对象、关键字、结果过滤。
- **导出**：CSV / JSON。
- **隐私**：openid / QQ 号哈希脱敏；提供「删除某对象全部数据」，支持保留策略自动清理。

### FR8 连接启动 Bot（P0）

- **连接列表页**：每个连接有独立的「启动 / 停止」开关与状态指示（未运行 / 启动中 / 运行中 / 异常）。
- **全部启停**：顶部提供「全部启动」「全部停止」快捷操作。
- **启动**：校验该连接配置完整性与预检，通过后启动该连接器实例；失败给出明确原因。
- **关停**：优雅停止该连接器，记录 `run_session.end_at`。
- **状态指示**：含连接器连接状态（已连接 / 断线 / 心跳时间）。
- **异常自恢复**：连接器断线自动重连；进程崩溃可重启。
- **预检清单**（分阻塞 / 警告）：
  | 预检项 | 级别 | 说明 |
  | --- | --- | --- |
  | 连接凭据是否填写 | **阻塞** | 缺失则禁止启动 |
  | 依赖是否可用 | **阻塞** | SDK 未装 / NapCat 未运行则禁止启动 |
  | 绑定人格是否有效 | **阻塞** | 无效则禁止启动 |
  | LLM 连通 / `apiKey` | **警告放行** | 未配置或不可用降级演示/兜底，仍可启动 |

  - 阻塞项失败禁止启动并给出错误；警告项提示但放行。

## 7. 数据模型（SQLite）

> 相比 v1.x，新增 `connection`（连接）、`persona`（人格主体）、`banword`（全局词库）等表；所有运行数据表增加 `connection_id` 维度。对象标识一律短哈希脱敏。

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `connection` | id, connection_id, name, type, status, persona_id, config_json(脱敏，含 riskConfirmed), created_at, updated_at | 连接实体（一级） |
| `persona` | id(persona_id), name, content_json(完整档案), builtin, created_at, updated_at | 人格主体（主存储） |
| `banword` | id, word, direction(in/out/both), enabled, created_at | 全局安全过滤词库 |
| `run_session` | id, connection_id, start_at, end_at, connector_type, persona, model, status | 运行会话（按连接） |
| `message_log` | id, **connection_id**, session_id, ts, channel, from_hash, group_hash, direction, content, reply, finish_reason, latency_ms, prompt_tokens, completion_tokens, msg_id, llm_ms, llm_attempts | 聊天记录 + 指标 |
| `llm_call` | id, **connection_id**, session_id, ts, model, prompt_tokens, completion_tokens, latency_ms, status, retry_cnt, error | LLM 调用明细 |
| `connection_event` | id, **connection_id**, ts, event, connector_type, detail | 连接器事件 |
| `abuse_event` | id, **connection_id**, ts, from_hash, reason, kind | 防滥用事件 |
| `persona_snapshot` | id, ts, persona_id, name, note | 人格操作历史 |
| `config_snapshot` | id, ts, scope(global/connection/connection_id), json(脱敏), note | 配置快照 |
| `app_meta` | key, value | 版本号、更新源等元信息 |

- 索引：`connection_id`、`ts`、`from_hash`、`channel`、`finish_reason`。
- 保留策略：按 `historyRetentionDays` / `logRetentionDays` 定期清理。

## 12. 风险与开放问题

| 风险 / 问题 | 等级 | 影响 | 应对 |
| --- | --- | --- | --- |
| 登录 QQ 号风控 / 封号 | 高 | 多账号登录放大封号面 | 明确提示用户自担；每连接独立限流；默认推荐官方 bot |
| 多连接资源占用 | 中 | 连接数多时内存/WS 连接数上升 | 连接器实例轻量化；限制最大连接数（可配）；监控资源 |
| 打包体积 / 杀软误报 | 中 | exe / 安装器被 Defender 误报 | 数字签名 / 加白名单 |
| 原生模块打包（TS） | 中 | `better-sqlite3` 打包复杂 | 优先 `node:sqlite`；必要时走 Tauri/Electron |
| 安装器 SmartScreen 拦截 | 中 | 未签名 setup.exe 触发警告 | 代码签名；便携版兜底 |
| QQ `openid` 不稳定 | 中 | 对象统计口径漂移 | 同连接 + 群内唯一口径固定；哈希展示 |
| token 与费用口径 | 中 | 不同网关计价不同 | 单价用户自填，按模型分别配置 |
| 上游模型波动 | 中 | 错误率/降级率偏高 | 区分我方/上游问题，日志分类 |
| 跨平台加密差异 | 低 | DPAPI 仅 Windows | Linux 用 keyring / 文件权限 + 可选加密 |
| OneBot 协议版本差异 | 低 | NapCat 不同实现字段不同 | 连接器按 OneBot v11 标准 + 兼容层 |

**开放问题（待确认）**：

3. 最大连接数上限是否需要在 P0 配置。

```json
  "emotionStyle": "温柔",
  "sampleDialogues": [
    { "user": "在吗", "bot": "在的呀～" },
    { "user": "今天好累", "bot": "辛苦啦，早点休息喵" }
  ],
  "bannedWords": ["政治敏感话题", "露骨色情描写", "辱骂攻击他人"],
  "stats": {
    "message_count": 900,
    "avg_len": 6,
    "tail_distribution": { "mao": 180, "soft": 120, "none": 530 }
  }
}
```

### 字段说明

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 人格唯一标识 |
| `name` | 是 | 显示名 |
| `profile` | 否 | 人格画像（页面展示用） |
| `profilePrompt` | **是** | 核心系统提示词；**必须包含 `{user_message}` 占位符** |
| `tags` | 否 | 人格标签 |
| `emotionStyle` | 否 | 主情绪风格 |
| `sampleDialogues` | 否 | 示例对话 `{user, bot}` |
| `bannedWords` | 否 | 安全红线词 |
| `stats` | 否 | 风格统计（可选） |

### 校验规则

- `name`、`profilePrompt` 缺失 → 校验失败，禁止被连接选用。
- `profilePrompt` 不含 `{user_message}` → 警告（仍可选用，建议补齐）。

### 在线生成人格（无鉴权）

在「人格管理 → 生成人格」中输入人设描述（可附示例对话），调用已配置的 LLM 产出符合上述格式的人格 JSON，预览后保存。
