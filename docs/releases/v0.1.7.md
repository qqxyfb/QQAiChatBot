# QQAiChatBot v0.1.7

体验修复版：解决「运行日志页进去是空的」与「聊天记录里表情包回复什么都不显示」两个问题。

## 1. 运行日志：进页面就能看到全部级别的历史日志

**问题**：日志页只订阅了实时推送（`/ws/logs`），进页面时既不回填已有日志，级别下拉也没有「全部」这一项，看到的就是一片空白——很像日志功能坏了。

**修复**：

- **进页面先回填**：打开日志页立即拉取最近 800 条（不传级别 = 全部级别），再接实时流；断线重连后按 `since` 游标补洞，不再漏日志。
- **级别下拉显式含「全部级别」**，并带每级条数（如 `全部级别（126）`、`WARN（3）`），一眼能看出日志到底有多少、都落在哪一级。
- **来源下拉默认「全部来源」**；筛选条件叠加过窄时给出「重置筛选」按钮，而不是空白页。
- **选中某个连接时同时保留系统级日志**：系统日志本身没有 connectionId，过去被直接过滤掉，连接一选就变空。
- 新日志到达自动滚到底部；点「暂停」后不再打断你的查看；行样式改为等宽 + 自动换行，长报错不再被截断。

## 2. 聊天记录：表情包回复不再空白，标签高亮成「图片」

**问题**：表情包标记 `[sticker:标签]` 在发给 QQ 前就被剥离，落库的 `reply` 只剩下文字。于是「只发表情包」的回复在聊天记录里是一条空白，完全看不出机器人发了图。

**修复**：

- 链路在写库时把命中的标签一并记录为 `[表情包:标签]`（真正发出后才会记，被频率闸门拦下的不记），正文与标签同时保留。
- 聊天记录页把该标记渲染成**紫色「图片」标签**：`🖼 表情包 · 开心`，与普通文字明显区分；兼容旧数据的 `[sticker:标签]` 写法。
- 纯表情包回复不再显示空白，只看到标签本身就说明「这条只发了图」；鼠标悬停有「已发送表情包（标签：xxx）」说明。
- 顺带修了两个记录页的可用性问题：
  - 进入页面自动带出最近 50 条消息，不再需要先点会话才看得到内容；
  - 点击左侧会话对象时筛选不生效（`setState` 异步导致的旧值问题）已修复，「清除对象筛选」也会真正重新加载。

## 升级说明

- 覆盖安装不影响现有数据（配置在 `%APPDATA%\QQAiChatBot\data`）。
- **本次修复只对升级后的新消息生效**：升级前已经落库的纯表情包回复正文本来就是空的，无法回溯补全标签。
