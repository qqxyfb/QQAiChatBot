# QQAiChatBot v0.1.5

修复版：解决「NapCat 接入报 401 无法启动」「模型配置太苛刻、报错看不全」「左侧菜单栏不固定」三个影响使用的问题。

## 修复内容

### 1. NapCat（登录 QQ 号）启动报 `Unexpected server response: 401`

**根因**：连接配置里**没有 Access Token 字段**，保存时还会把 `account.accessToken` 整体丢弃；
而 NapCat 的 OneBot 11 WebSocket 服务端一旦开启 token 校验，握手一律返回 401。

**修复**：

- 连接配置新增 **Access Token**（密文输入、可切换明文）与 **WebSocket 路径**（默认 `/`）两个字段，并随连接一起保存。
- 正向 WS 握手改为**双方式兼容**：先试 `Authorization: Bearer <token>`，被 401/403 拒绝后自动改用 `?access_token=<token>` 重试；
  不同 NapCat 版本/反代对 token 的读取方式不同，用户不必再猜。
- 错误提示全部中文化、可操作：401（未填 token / token 不匹配）、404（路径不对）、502/503（NapCat 未就绪）、
  连接被拒绝（NapCat 未启动或端口不对）、超时、地址解析失败，均说明「该去改哪个配置」并给出目标地址（token 已打码）。
- 启动预检新增 **NapCat 端口探活**：端口不通直接阻塞并说明原因，而不是 running 之后静默。
- 反向 WS 的 token 校验同时接受 `Authorization` 头与 `?access_token=`，并修正「反向 WS 暂未实现」的过时文案。
- 只有在**曾经连接成功**后才自动重连，避免 401/端口错时每 5 秒空转。

### 2. 模型配置太苛刻、不能选模型、报错看不全

- **新增「获取模型」按钮**：从服务端 OpenAI 兼容 `/v1/models` 拉取候选模型，模型字段改为可搜索下拉（仍支持自由输入）。
  核心配置页与连接「LLM 覆盖」抽屉都已接入。
- **模型名不在列表里不再阻塞启动**：预检分级调整——端口/LLM 不可达、LLM 鉴权失败仍然是阻塞项；
  模型不在 `/v1/models` 列表只作为**提示**（中转站/代理的模型列表常常不完整或用别名），允许继续启动。
- **报错信息完整可见**：「启动失败」弹窗改为可滚动、可复制的完整文本，并列出**全部预检明细**（通过 / 未通过、阻塞 / 提示）；
  「测试 LLM」失败时展示上游原始错误，并提供「查看完整错误」弹窗；「全部启动」失败也会列出每个连接的失败原因。
- 测试 LLM 失败时自动附带可选模型列表，`HTTP 400` 这类无信息错误升级为「模型名不存在 / 参数不支持 + 上游原因 + 可选项」。

### 3. 左侧菜单栏不固定

- 布局改为 `100vh` 固定高度：侧边栏独立滚动，只有右侧内容区滚动。
  滚动长页面时左侧菜单不会再跟着下滑。

## 升级说明

- 版本 `0.1.5`，直接覆盖安装即可；数据目录（`%APPDATA%\QQAiChatBot\data`）与已有配置、连接、人格、聊天记录保持兼容。
- 已配置过的 NapCat 连接：打开「连接配置」，把 NapCat 里的 Token 填到 **Access Token**（不要带 `Bearer ` 前缀）后保存再启动。

## 回归验证

- `npm run build && npm run verify`：服务端托管前端 / SPA 深层链接 / health 自检通过。
- 模拟 NapCat 服务端（只认 `access_token` 查询参数）：连接器第 1 次 401 后自动改用查询参数**连接成功**。
- 模拟 401 错误：提示「未填写 Access Token」/「Access Token 不被接受」，token 在提示里已打码。
- 预检分级：端口不通 → 阻塞；模型名不在列表 → 仅提示，连接可正常启动。
- Electron 实测：内容区滚动 700px，`document.scrollingElement.scrollTop = 0`，侧边栏与菜单位置不变。
