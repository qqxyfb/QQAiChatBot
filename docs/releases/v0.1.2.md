# QQAiChatBot v0.1.2

修复版：解决点击「启动 / 停止 / 全部启动 / 全部停止 / 下载更新」时报
`Body cannot be empty when content-type is set to 'application/json'` 的问题，并为更新下载补上代理回退与可读的错误提示。

## 问题原因

前端请求封装对**所有**请求都加了 `Content-Type: application/json`，但上面这些操作本来就没有请求体。Fastify v5 的 JSON 解析器遇到「声明 JSON + 空 body」会直接抛
`FST_ERR_CTP_EMPTY_JSON_BODY`（`Body cannot be empty when content-type is set to 'application/json'`），请求根本没进业务逻辑。

也就是说 0.1.x 里这些按钮一直是坏的，只是「下载更新」用得最多才被发现。

## 本版修复

- **前端请求封装**：只有真正带 body 时才声明 `Content-Type`；GET / DELETE / 无参 POST 不再发送空的 JSON 头。
- **服务端宽容解析**：自定义 `application/json` 解析器把空 body 视为「无参数」，第三方脚本、旧客户端用 `-H 'Content-Type: application/json'` 空 body 调用也不会再被 400 拦住；非法 JSON 仍返回 400（不再是 500）。
- **空配置校验**：`PUT /api/config` 传空 body 时提示「配置内容为空」，而不是 `Cannot read properties of undefined`。
- **更新下载支持代理**：Node 原生 fetch 不读 `HTTPS_PROXY`，受限网络下只能得到 `fetch failed`。现在先直连，失败后按 `HTTPS_PROXY / HTTP_PROXY / ALL_PROXY`（大小写均可）自动用代理重试一次，直连可用时行为不变。
- **下载失败提示**：超时（安装包 100MB+，GitHub 资源被限速很常见）会明确提示「下载超时」并给出 Release 页面地址引导手动下载；其他网络错误会带上具体错误码与代理建议。
- **下载按钮体验**：按钮进入 loading 态并显示「下载中…」，避免重复点击；失败原因改用弹窗展示（原文较长）。

## 升级须知

- 直接运行 0.1.2 安装包覆盖安装即可，`%APPDATA%\QQAiChatBot` 下的配置、人格、聊天记录、日志均保留。
- 若「下载更新」仍超时（GitHub 资源在国内常被限速），两种办法：
  1. 启动应用前设置 `HTTPS_PROXY=http://127.0.0.1:7890`（换成你自己的代理端口），应用会在直连失败后自动走代理；
  2. 直接到 Release 页面用浏览器或下载工具取安装包，再手动覆盖安装。
- 0.1.1 及更早版本无法通过内置按钮完成下载（就是本版修的问题），请手动下载 0.1.2。

## 已知限制

- exe 未做代码签名，首次运行可能触发 SmartScreen 提示（更多信息 → 仍要运行）。
- 下载过程没有进度条，100MB+ 的安装包在慢速网络下需要等待，或按上面的方式手动下载。
- 登录 QQ 号（OneBot v11）属非官方途径，存在封号风险，建议优先使用官方机器人。
- 开启「外网访问」时静态资源同样需要 `Bearer` 令牌，浏览器直接访问会 401，建议通过反向代理对外提供页面。
