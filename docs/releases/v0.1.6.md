# QQAiChatBot v0.1.6

体验修复版：解决「群聊被 @ 后回复看不出在回谁」与「表情包刷屏、频率无法控制」两个问题。

## 1. 群聊被 @ 时改为**引用回复**

**问题**：群聊里被 @ 之后，回复只是一条普通消息发出去，上下文一多就分不清在回谁。

**修复**：

- 新增 OneBot v11 的 `reply` 消息段：回复时把原消息 id 带在最前面，客户端显示成「引用某某的消息」。
- 连接配置新增 **群聊引用回复** 三档策略（默认「被 @ 时引用」）：
  - **被 @ 时引用（推荐）**：只有被 @ 的回复才引用，不打扰其他闲聊；
  - **群聊每条都引用**：每条回复都挂引用（适合高度依赖上下文的场景）；
  - **从不引用**：保持原样，只发消息。
- 私聊不会带引用（没有引用语义）；引用段与表情包/语音段可以共存，顺序为「引用 → 文字 → 媒体」。
- 链路日志会标注本条是否走了引用回复，便于排查。
- 改动即时生效：保存连接配置后无需重启连接（下一条消息就带上）。

> QQ 官方机器人（AppID 接入）的消息形态由平台决定，该项对官方 Bot 置灰，不影响其现有被动回复（`msg_id`）。

## 2. 表情包频率可控（不再刷屏）

**问题**：之前只靠提示词建议「若适合可追加 `[sticker:标签]`」，模型几乎每条都发，观感就是刷屏，用户无法控制。

**修复**：把「发不发」从模型手里收回到程序侧，三重闸门 + 一个开关：

| 控制项 | 说明 | 默认 |
| --- | --- | --- |
| 允许发表情包 | 总开关，关掉后即使模型输出标记也不发图 | 开 |
| 发送概率 | 模型想发时，实际发出去的概率（0~1） | 0.3 |
| 最小间隔（秒） | 同一会话两次表情包的最短间隔，防止连发 | 120 |

另有 **频率预设** 一键套用：克制（10% / 5 分钟）、适中（30% / 2 分钟）、活跃（60% / 30 秒）、关闭。

实现上做了两层收敛，而不是只做事后拦截：

1. **源头降频**：冷却期内，提示词里**不再提供表情包标签枚举**，模型根本不会尝试发表情包；同时提示词语气改为「表情包是可选点缀，多数回复只写文字」。
2. **落地闸门**：即使模型仍输出了标记，也要再过「开关 → 冷却 → 概率」三关；命中后按标签随机取图，无候选则降级纯文字。

其他配套修正：

- 表情包改为**文字 + 配图**一起发（此前是「只发图、不配文字」），不再丢失回复正文；
- 极端情况（模型只输出标记却被拦下）不会发出空消息，改用文字占位并记 WARN 日志；
- 上下文只记录纯文本，表情包记为 `[表情包]`，不污染模型记忆；
- 每次发图/跳过都会在「运行日志」记 DEBUG 原因（冷却剩余秒数、概率 roll 值、标签无图片等），方便调到合适的频率。

## 升级说明

- 覆盖安装即可，配置与数据（`%APPDATA%\QQAiChatBot\data`）不受影响。
- 老人格没有表情包频率配置时，自动按新默认值（30% / 120 秒）执行 —— 装完就能感到表情包明显变少。
- 如需调整：**人格管理 → 编辑 → 表情包频率**；引用回复在 **连接管理 → 配置 → 聊天配置 → 群聊引用回复**。
