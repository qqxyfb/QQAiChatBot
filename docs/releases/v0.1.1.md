# QQAiChatBot v0.1.1

修复版：解决 **Windows 安装版 / 便携版启动后窗口黑屏，只显示一行 `{"message":"Route GET:/ not found",...}`** 的问题，并补充桌面端启动自检与诊断能力。

## 问题原因

服务核心由 Electron 以子进程（`ELECTRON_RUN_AS_NODE`）拉起，而服务端用 `process.cwd()` 拼接前端目录 `web/dist`。子进程的 cwd 取决于启动方式（快捷方式、便携版临时解压目录、命令行），并不等于 `app.asar` 所在目录，因此：

1. 找不到 `web/dist/index.html`，`@fastify/static` 与 SPA 兜底都没有注册；
2. 窗口访问 `GET /` 命中 Fastify 默认 404，返回一行 JSON；
3. `loadURL` 对 404 也算加载成功，重试逻辑不触发 —— 界面就停在黑屏。

## 本版修复

- **前端目录解析与 cwd 解耦**：桌面端通过 `QQAICHATBOT_WEB_DIR` / `QQAICHATBOT_APP_ROOT` / `QQAICHATBOT_RESOURCE_DIR` 显式下发目录，服务端用 `__dirname` 兜底（asar 内同样成立）。
- **静态托管兜底**：`setNotFoundHandler` 恒定注册；产物缺失时返回可读的 503 诊断页（列出已尝试路径与修复建议），不再输出裸 404 JSON。
- **桌面端启动顺序**：单实例锁 → 端口占用时自动从 8700 顺延 → 先轮询 `/api/health` 确认就绪再加载界面；启动失败或服务中途崩溃时显示诊断页（含服务日志尾部与数据目录）。
- **启动日志**：全过程写入 `%APPDATA%\QQAiChatBot\electron.log`（端口、健康检查结果、加载结果、退出码），便于反馈问题。
- **打包**：`web/dist`、`db/migrations` 从 asar 解包，静态文件读取更稳。
- **托盘图标**：补上 `resources/tray.png`（此前图标缺失会导致托盘创建失败、关窗直接退出）。
- **更新检测误报**：GitHub tag 的 `v` 前缀不再参与比较，并改为逐段数值比较——只有线上版本确实更高时才提示，修复首屏常驻「发现新版本 0.1.0（当前 0.1.0）」。
- **回归脚本**：`npm run verify` 从一个与项目无关的临时目录启动 `dist/main.js`，断言 `/` 与 `/config` 均返回 `index.html`、`/api/health` 报告 `web:true`，防止该问题回归。
- 服务端补全 `/api/health` 的 `web` 字段，可直接判断前端产物是否就绪。

## 下载

| 产物 | 适用场景 | 说明 |
| --- | --- | --- |
| `QQAiChatBot-Setup-0.1.1-x64.exe` | Windows 10/11 | NSIS 安装版：可选安装目录、快捷方式、卸载项，覆盖安装保留数据 |

每个 exe 附带 `.sha256` 校验文件，客户端「检查更新」下载后会自动校验。

## 升级须知

- 已安装 0.1.0 的用户可直接运行 0.1.1 安装包覆盖安装，`%APPDATA%\QQAiChatBot` 下的配置、人格、聊天记录、日志均保留。
- 从 0.1.0 起客户端内置的「检查更新」会在本版发布后提示 v0.1.1；若仓库仍为 private，需在「核心配置 → 更新」填写具有 `repo` 读取权限的 PAT。
- 若仍遇到启动异常，先看 `%APPDATA%\QQAiChatBot\electron.log`，再看「运行日志 → 服务」；窗口内的诊断页会直接列出服务进程输出。

## 已知限制

- exe 未做代码签名，首次运行可能触发 SmartScreen 提示（更多信息 → 仍要运行）。
- 登录 QQ 号（OneBot v11）属非官方途径，存在封号风险，建议优先使用官方机器人。
- 本版仅发布 Windows 产物，Linux 走源码部署。
- 开启「外网访问」时静态资源同样需要 `Bearer` 令牌，浏览器直接访问会 401，建议通过反向代理 + 令牌注入的方式对外提供页面（后续版本再调整）。
